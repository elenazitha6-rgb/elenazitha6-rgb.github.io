## В чём разница между HTTP-прокси и SOCKS5-прокси?

**HTTP-прокси** понимает HTTP: он читает ваши веб-запросы, а для HTTPS открывает туннель методом `CONNECT`. **SOCKS5-прокси** работает уровнем ниже: он передаёт TCP-соединение к указанному вами адресу назначения, не разбирая, что движется внутри него. Поэтому SOCKS5 подходит для большего числа программ, а HTTP — естественный выбор для веб-инструментов.

| | HTTP-прокси | SOCKS5-прокси |
|---|---|---|
| Что понимает | HTTP-запросы | Ничего о трафике внутри |
| Типичный трафик | Веб-страницы, API, HTTPS через `CONNECT` | Любое TCP-соединение: веб, SSH, мессенджеры |
| Аутентификация | Аутентификация на прокси в HTTP-заголовках | Логин и пароль при SOCKS-рукопожатии |
| UDP | Нет | Предусмотрен протоколом, но поддерживается не у всех провайдеров |
| Лучше всего поддерживается | Браузерами, `curl`, библиотеками для сбора данных | Приложениями с настройкой SOCKS, SSH-туннелями, многими настольными клиентами |

## Как HTTPS-запрос проходит через каждый из них?

С HTTP-прокси клиент сначала отправляет текстовую строку `CONNECT` с адресом назначения, после чего прокси открывает туннель. В случае SOCKS5 клиент и прокси проводят короткое бинарное рукопожатие, а запрос указывает адрес назначения в компактном бинарном формате. Оба формата сообщают прокси, куда вы направляетесь, и ни один из них сам по себе не шифрует участок до прокси.

```text
CONNECT example.com:443 HTTP/1.1
Host: example.com:443
Proxy-Authorization: Basic ...
```

Метод `CONNECT` описан в [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110#name-connect). Рукопожатие SOCKS5 — в [RFC 1928](https://www.rfc-editor.org/rfc/rfc1928), а шаг с логином и паролем — в [RFC 1929](https://www.rfc-editor.org/rfc/rfc1929).

Практическое следствие: некоторые сети анализируют текстовые строки `CONNECT`, но бинарное рукопожатие SOCKS5 разбирают иначе. В такой сети один протокол может сбрасываться, а другой — работать. Считайте это шагом диагностики, а не правилом: в других сетях всё может быть иначе.

## Какой протокол выбрать?

Выбирайте по тому, что поддерживает ваше ПО. Если доступны оба варианта, SOCKS5 универсальнее, а HTTP привычнее.

- **Выбирайте HTTP,** если в инструменте есть только поле для HTTP-прокси, если вы работаете с веб-запросами и API или если нужна максимальная совместимость с библиотеками для сбора данных и браузерами.
- **Выбирайте SOCKS5,** если приложение не является веб-клиентом, если в программе SOCKS5 указан как вариант или если нужна одна настройка для нескольких протоколов.
- **Не выбирайте ни один из них,** если нужен UDP, например для некоторых игр или голосовых звонков. Используйте VPN-клиент.

## Что поддерживает HTTP/SOCKS5-прокси AnboVPN?

HTTP/SOCKS5-прокси AnboVPN выдаёт каждому вашему профилю браузера или скрипту отдельный прокси-аккаунт: HTTP (включая HTTPS-туннели) и SOCKS5 работают с одним набором учётных данных. Эти сведения проверены по сайту AnboVPN в ноябре 2026 г.

- Один аккаунт работает для обоих протоколов, а необязательный белый список исходных IP позволяет одобренным адресам подключаться без логина и пароля.
- Хост, порты, логин и пароль показаны в вашем аккаунте в однострочном формате `host:port:username:password`, который удобно вставлять в инструменты для профилей браузера. Если профилей много, скопируйте все данные сразу.
- Используются те же трафик и IP-ресурс, что и у вашего выделенного IP.
- UDP в SOCKS5 не поддерживается, порт 25 и доступ к внутренним сетям не предоставляются.
- Прокси включается для каждого узла отдельно. Если для IP нет карточки прокси, на этом узле он ещё не включён, а сам IP по-прежнему можно использовать через клиент или ссылку-подписку.

## Как проверить прокси?

Отправьте один запрос через прокси на сервис, который показывает ваш адрес, и убедитесь, что это адрес прокси. В `curl` подставьте вместо заглушек свои данные:

```bash
# SOCKS5 (socks5h позволяет прокси самому разрешать доменное имя)
curl -x socks5h://USERNAME:PASSWORD@HOST:PORT https://www.anbovpn.com/ip

# HTTP
curl -x http://USERNAME:PASSWORD@HOST:PORT https://www.anbovpn.com/ip
```

В ответе вы увидите адрес и местоположение, которые видит сайт. Если один протокол не срабатывает, запустите другой с теми же данными. Проверить сразу несколько прокси можно и бесплатными инструментами: [проверкой HTTP-прокси](https://www.anbovpn.com/ru/tools/http-proxy-test) и [проверкой SOCKS5-прокси](https://www.anbovpn.com/ru/tools/socks5-proxy-test).
