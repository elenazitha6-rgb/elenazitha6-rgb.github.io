## Коротко: что такое SOCKS5-прокси

**SOCKS5-прокси** — это промежуточный сервер, который по протоколу SOCKS версии 5 (RFC 1928) открывает TCP-соединение с указанным вами адресом и дальше пересылает байты, не разбирая их содержимое. **HTTP-прокси**, напротив, понимает HTTP: читает запросы, а для HTTPS по команде `CONNECT` открывает туннель.

Выбор сводится к совместимости. Поле «HTTP-прокси» есть почти в любом веб-инструменте, а SOCKS5 подходит для более широкого круга программ. Быстрее ни один из них не является.

## Что происходит на проводе

Оба протокола сообщают прокси, куда вы хотите попасть, и ни один сам по себе не шифрует участок до прокси. Различается формат: HTTP-прокси получает текстовую строку `CONNECT`, SOCKS5-прокси — короткий двоичный обмен.

```text
CONNECT example.com:443 HTTP/1.1
Host: example.com:443
Proxy-Authorization: Basic dXNlcjpwYXNz

HTTP/1.1 200 Connection Established
```

То же самое через SOCKS5 с авторизацией по логину и паролю (байты в hex):

```text
клиент → прокси: 05 01 02                версия 5, один метод: 02 (логин и пароль)
прокси → клиент: 05 02                   выбран метод 02
клиент → прокси: 01 04 "user" 04 "pass"  подсогласование по RFC 1929
прокси → клиент: 01 00                   успех
клиент → прокси: 05 01 00 03 0B "example.com" 01 BB   CONNECT, имя хоста, порт 443
прокси → клиент: 05 00 00 01 ...         успех, дальше идут байты приложения
```

Метод `CONNECT` описан в [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110#name-connect), рукопожатие SOCKS5 в [RFC 1928](https://www.rfc-editor.org/rfc/rfc1928), а проверка логина и пароля в [RFC 1929](https://www.rfc-editor.org/rfc/rfc1929). Пароль и там, и там уходит без шифрования (в схеме Basic это всего лишь base64), так что участок до прокси при желании защищайте отдельно.

Практическое следствие: некоторые сети по-разному реагируют на текстовый `CONNECT` и на двоичное рукопожатие SOCKS5, и бывает, что один протокол сбрасывается, а второй проходит. Это приём диагностики, а не правило.

## Сравнение по существенным признакам

Ниже собраны отличия, которые влияют на выбор. Таблица не про скорость: по скорости протоколы равноценны, всё решает сетевой путь.

| Признак | HTTP-прокси | SOCKS5-прокси |
|---|---|---|
| Что понимает | HTTP-запросы | Ничего о трафике внутри |
| Что передаёт | Веб-запросы, API, HTTPS через `CONNECT` | Любое TCP-соединение: веб, SSH, почтовые и чат-клиенты |
| Аутентификация | Заголовок `Proxy-Authorization` | Логин и пароль в рукопожатии (RFC 1929) |
| UDP | Нет | Описан в протоколе, но поддерживается не везде |
| Чаще всего встречается | Браузеры, `curl`, библиотеки для HTTP-запросов, парсеры | Программы с полем SOCKS, SSH-туннели, десктопные клиенты |

## DNS и схема прокси: socks5 или socks5h

От схемы в адресе прокси зависит, кто превратит имя сайта в IP. В `curl` схема `socks5://` разрешает имя на вашей стороне, а `socks5h://` передаёт имя прокси. Если важно, чтобы DNS-запросы не уходили с вашей машины, берите `socks5h`. Для HTTP-прокси при `CONNECT` имя хоста и так уходит прокси.

## Как выбрать

Ориентируйтесь на то, что умеет ваше ПО. Если поддерживаются оба варианта, SOCKS5 универсальнее, HTTP привычнее.

- **HTTP-прокси** — когда в настройках есть только поле HTTP-прокси, когда вы работаете с веб-запросами и API или пишете парсер на библиотеке с поддержкой HTTP-прокси.
- **SOCKS5-прокси** — когда программа не веб-клиент, в её списке есть SOCKS5 или нужен один параметр на несколько прикладных протоколов поверх TCP.
- **Ни тот ни другой** — когда нужен UDP, например для голосовых звонков или части игр. Здесь нужен клиент AnboVPN.

## HTTP/SOCKS5-прокси в AnboVPN: что есть и чего нет

HTTP/SOCKS5-прокси AnboVPN выдаёт каждому профилю браузера или скрипту свой прокси-аккаунт: HTTP (включая туннели HTTPS) и SOCKS5 работают на одном наборе учётных данных. Сведения о продукте сверены с официальным сайтом AnboVPN в ноябре 2026 г.

- Есть необязательный белый список исходных IP: подключения с указанных адресов проходят без логина и пароля.
- Данные доступа выдаются в одну строку `хост:порт:логин:пароль`, а кнопка копирует их все сразу, что удобно для массового импорта в профили браузера. Порты видны в аккаунте.
- Прокси делит пакет трафика и IP с [выделенным IP](/ru/posts/dedicated-ip-vs-shared-ip/).
- UDP в SOCKS5 не поддерживается, порт 25 и доступ к внутренним сетям не предоставляются.
- Прокси включается для каждого узла отдельно. Если у IP нет карточки прокси, узел пока не включён, но сам IP по-прежнему работает через клиент или ссылку подписки.

## Проверка из командной строки

Отправьте через прокси один запрос к сервису, который возвращает ваш адрес, и убедитесь, что адрес принадлежит прокси. Подставьте свои данные:

```bash
# SOCKS5; socks5h — имя сайта разрешает прокси
curl -x socks5h://ЛОГИН:ПАРОЛЬ@ХОСТ:ПОРТ https://www.anbovpn.com/ip

# HTTP
curl -x http://ЛОГИН:ПАРОЛЬ@ХОСТ:ПОРТ https://www.anbovpn.com/ip
```

Если в пароле есть спецсимволы (`@`, `:`, `/`), закодируйте их в процентной записи или передайте данные через `--proxy-user ЛОГИН:ПАРОЛЬ`. Список в формате `хост:порт:логин:пароль` проверяется циклом:

```bash
while IFS=: read -r host port user pass; do
  printf '%s:%s -> ' "$host" "$port"
  curl -s -m 15 -x "socks5h://$user:$pass@$host:$port" https://www.anbovpn.com/ip
done < proxies.txt
```

Без командной строки то же сделают бесплатные инструменты: [проверка HTTP-прокси](https://www.anbovpn.com/ru/tools/http-proxy-test) и [проверка SOCKS5-прокси](https://www.anbovpn.com/ru/tools/socks5-proxy-test). Если через один адрес нужно пустить сразу все устройства в сети, посмотрите статью про [сетевой шлюз](/ru/posts/network-gateway-explained/).
