## SOCKS5プロキシとは？HTTPプロキシとの違い

SOCKS5プロキシ（SOCKS5 proxy）とは、クライアントが指定した宛先へのTCP接続を、通信の中身を解釈せずに中継するプロキシのことです。HTTPプロキシがHTTPのリクエストを読み取って扱うのに対し、SOCKS5はウェブ、SSH、チャットアプリなど、プロトコルを問わず通せます。

先に答えを言うと、選ぶ基準は「速さ」ではなく「ソフトの設定欄に何があるか」です。両者の違いを表にまとめます。

| 比べる点 | HTTPプロキシ | SOCKS5プロキシ |
|---|---|---|
| 通信の扱い | HTTPのリクエストを理解する | 中身は解釈せず、接続だけ中継する |
| 得意な通信 | ウェブページ、API、HTTPS（`CONNECT` 経由） | ウェブ、SSH、チャットなど任意のTCP接続 |
| 認証 | HTTPヘッダーでのプロキシ認証 | ハンドシェイク時のユーザー名とパスワード |
| UDP | 扱わない | 仕様上は定義があるが、対応は事業者による |
| よく使われる場面 | ブラウザ、`curl`、スクレイピング用ライブラリ | SOCKS設定のあるアプリ、SSHトンネル |

## 設定画面で迷ったときの3つの判断軸

判断軸は3つです。上から順に確認すると、ほとんどの場合は答えが出ます。

1. **設定欄に何と書いてあるか。** 「HTTPプロキシ」しかなければHTTP、「SOCKS」「SOCKS5」の欄があればSOCKS5も選べます。両方あるときは、SOCKS5のほうが汎用的で、HTTPのほうが一般的です。
2. **通信がウェブ系かどうか。** ブラウザやAPI、スクレイピング系のライブラリならHTTPが自然です。SSHやチャットなどウェブ以外のソフトなら、SOCKS5が向いています。
3. **UDPが必要かどうか。** ゲームや音声通話など、UDPを使うソフトにはプロキシは向きません。VPNクライアントを使ってください。

## HTTPSの通信は、どのようにプロキシを通るのか

HTTPプロキシでは、まずクライアントが宛先を示す `CONNECT` の1行を平文で送り、プロキシがトンネルを開きます。SOCKS5では、クライアントとプロキシが短いバイナリ形式のハンドシェイクを行い、宛先を伝えます。どちらの場合も、プロキシは宛先を知りますが、HTTPSの中身までは通常読めません。また、プロキシまでの区間は、どちらもそれだけでは暗号化されません。

```text
CONNECT example.com:443 HTTP/1.1
Host: example.com:443
Proxy-Authorization: Basic ...
```

`CONNECT` メソッドは[RFC 9110](https://www.rfc-editor.org/rfc/rfc9110#name-connect)、SOCKS5のハンドシェイクは[RFC 1928](https://www.rfc-editor.org/rfc/rfc1928)、ユーザー名とパスワードによる認証は[RFC 1929](https://www.rfc-editor.org/rfc/rfc1929)で定められています。

実務上の豆知識を1つ。ネットワークによっては、平文の `CONNECT` は検査されても、SOCKS5のハンドシェイクは別の扱いになる場合があります。片方だけがリセットされるときは、もう片方を試すのも切り分けの手です。ただし、すべての環境でそうなるとは限りません。

## AnboVPNのHTTP/SOCKS5プロキシの対応範囲

AnboVPNのHTTP/SOCKS5プロキシでは、ブラウザプロファイルやスクリプトごとに、専用のプロキシアカウントを持てます。HTTP（HTTPSトンネルを含む）とSOCKS5を、1組の認証情報で使えます。以下の内容は、2026年11月にAnboVPN公式サイトで確認しました。

- **認証情報：** ホスト、ポート、ユーザー名、パスワードがアカウント内に表示されます。`host:port:username:password` の1行形式で、まとめてコピーできます。ブラウザプロファイル系のツールに貼り付けやすく、多数管理する場合にも便利です。
- **IPホワイトリスト（許可リスト）：** 接続元IPを登録する設定は任意です。登録した接続元からは、ユーザー名とパスワードなしで接続できます。
- **共有するもの：** 専用IPと同じデータパックとIPを使います。
- **非対応：** SOCKS5のUDP、25番ポート、イントラネットへのアクセスは提供していません。
- **開通の単位：** プロキシはノードごとに有効化されます。IPにプロキシのカードが表示されなければ、そのノードはまだ有効化されていません。IP自体は、クライアントまたはサブスクリプションリンクから引き続き使えます。

販売中の内容は、[HTTP/SOCKS5プロキシのページ](https://www.anbovpn.com/ja/proxy-ip)でご確認ください。

## curlで動作を確認する

プロキシ経由でアドレスを返すサービスにアクセスし、返ってきたアドレスがプロキシのものか確認します。`USERNAME` などは、ご自身の情報に置き換えてください。

```bash
# SOCKS5（socks5h を使うと、ドメイン名の解決もプロキシ側で行います）
curl -x socks5h://USERNAME:PASSWORD@HOST:PORT https://www.anbovpn.com/ip

# HTTP
curl -x http://USERNAME:PASSWORD@HOST:PORT https://www.anbovpn.com/ip
```

応答には、相手のサイトから見えているアドレスと所在地が表示されます。複数のプロキシをまとめて確認するなら、無料の[HTTPプロキシチェッカー](https://www.anbovpn.com/ja/tools/http-proxy-test)と[SOCKS5プロキシチェッカー](https://www.anbovpn.com/ja/tools/socks5-proxy-test)も使えます。

## つながらないときの確認ポイント

つながらないときは、症状ごとに原因を切り分けます。

| 症状 | 確認すること |
|---|---|
| 認証エラー（HTTP 407 など） | ユーザー名・パスワード、またはIPホワイトリストの登録内容を見直します。 |
| 片方のプロトコルだけ失敗する | 同じ認証情報のまま、もう片方のプロトコルを試します。 |
| ポートが分からない | アカウント内に表示されているホストとポートを使います。 |
| プロキシのカードが表示されない | そのノードは未開通です。IPはクライアントなどから使えます。 |
| 25番ポートや社内LANに届かない | どちらも提供していないため、仕様どおりの動作です。 |

関連する話題として、プロキシの背後にあるアドレスの種類は[専用IPと共有IPの違い](/ja/posts/dedicated-ip-vs-shared-ip/)に、プロキシを使わず端末ごとまとめて接続する方法は[ネットワークゲートウェイの解説](/ja/posts/network-gateway-explained/)にあります。

## まとめ

HTTPかSOCKS5かは、速度ではなく、使うソフトの設定欄と通信の種類で決まります。

- 設定欄がHTTPだけならHTTP、SOCKSの欄があればSOCKS5も選べる
- ウェブ系はHTTP、それ以外はSOCKS5が向く
- UDPが必要なら、プロキシではなくVPNクライアントを使う
- AnboVPNは、1組の認証情報でHTTPとSOCKS5の両方を使える
- 動作確認は `curl` で。SOCKS5では `socks5h://` が確実
