## HTTPプロキシとSOCKS5プロキシの違いは何ですか？

**HTTPプロキシ**はHTTPを理解します。ウェブのリクエストを読み取り、HTTPSでは `CONNECT` メソッドでトンネルを開きます。**SOCKS5プロキシ**は1段下の層で動き、指定された宛先へのTCP接続を、中身を解釈せずに中継します。そのため、SOCKS5はより多くの種類のソフトウェアに向いており、HTTPはウェブ系のツールに自然に合います。

| | HTTPプロキシ | SOCKS5プロキシ |
|---|---|---|
| 理解する内容 | HTTPリクエスト | 通信の中身は理解しない |
| 主な通信 | ウェブページ、API、`CONNECT` 経由のHTTPS | ウェブ、SSH、チャットアプリなど、あらゆるTCP接続 |
| 認証 | HTTPヘッダーでのプロキシ認証 | SOCKSハンドシェイク中のユーザー名とパスワード |
| UDP | 非対応 | プロトコル上は定義されているが、すべての事業者が対応しているわけではない |
| 対応が手厚いもの | ブラウザ、`curl`、スクレイピング用ライブラリ | SOCKS設定のあるアプリ、SSHトンネル、多くのデスクトップクライアント |

## HTTPSリクエストは、それぞれどう通りますか？

HTTPプロキシでは、クライアントがまず宛先を示す平文の `CONNECT` 行を送り、そのあとプロキシがトンネルを開きます。SOCKS5では、クライアントとプロキシが短いバイナリのハンドシェイクを行い、リクエストが簡潔なバイナリ形式で宛先を示します。どちらの形式でも、プロキシには宛先が伝わります。また、プロキシまでの区間は、どちらもそれだけでは暗号化されません。

```text
CONNECT example.com:443 HTTP/1.1
Host: example.com:443
Proxy-Authorization: Basic ...
```

`CONNECT` メソッドは、[RFC 9110](https://www.rfc-editor.org/rfc/rfc9110#name-connect)で定義されています。SOCKS5のハンドシェイクは[RFC 1928](https://www.rfc-editor.org/rfc/rfc1928)、ユーザー名とパスワードの手順は[RFC 1929](https://www.rfc-editor.org/rfc/rfc1929)にあります。

実用上の注意点が1つあります。ネットワークによっては、平文の `CONNECT` 行を検査する一方で、バイナリのSOCKS5ハンドシェイクは同じようには読まないことがあります。そうしたネットワークでは、片方のプロトコルがリセットされても、もう片方は接続できる場合があります。ほかのネットワークでは挙動が異なるため、ルールではなく、トラブルシューティングの手順の1つとして考えてください。

## どちらを選べばよいですか？

使うソフトが対応している方式で選びます。両方使える場合、SOCKS5はより汎用的で、HTTPはより一般的な選択肢です。

- **HTTPを選ぶ場合：** ツールにHTTPプロキシの入力欄しかないとき、ウェブのリクエストやAPIを扱うとき、スクレイピング用ライブラリやブラウザとの幅広い互換性を重視したいとき。
- **SOCKS5を選ぶ場合：** アプリがウェブクライアントではないとき、ソフトがSOCKS5を選択肢として挙げているとき、1つの設定で複数のプロトコルをカバーしたいとき。
- **どちらも選ばない場合：** 一部のゲームや音声通話など、UDPが必要なとき。VPNクライアントを使ってください。

## AnboVPNのHTTP/SOCKS5プロキシは、何に対応していますか？

AnboVPNのHTTP/SOCKS5プロキシでは、ブラウザプロファイルやスクリプトごとに専用のプロキシアカウントを持てます。HTTP（HTTPSトンネルを含む）とSOCKS5を、1組の認証情報で使えます。以下の内容は、2026年11月にAnboVPN公式サイトで確認しました。

- 1つのアカウントで、両方のプロトコルを使えます。接続元IPのホワイトリスト（許可リスト）は任意で設定でき、承認済みのアドレスからは、ユーザー名とパスワードなしで接続できます。
- ホスト、ポート、ユーザー名、パスワードはアカウント内に表示されます。ブラウザプロファイル系のツールに貼り付けやすい、`host:port:username:password` の1行形式です。多数管理する場合は、まとめてコピーできます。
- 専用IPと同じ通信量とIPリソースを使います。
- SOCKS5のUDPには対応しておらず、25番ポートと内部ネットワークへのアクセスは提供していません。
- プロキシ接続は、ノードごとに有効化されます。IPにプロキシのカードが表示されない場合は、そのノードがまだ有効化されていません。そのIPは、クライアントまたはサブスクリプションリンクから引き続き使えます。

販売中の内容は、[HTTP/SOCKS5プロキシのページ](https://www.anbovpn.com/ja/proxy-ip)をご覧ください。

## プロキシはどうやってテストしますか？

アドレスを返してくれるサービスに、プロキシ経由でリクエストを1回送り、返ってきたアドレスがプロキシのものか確認します。`curl` を使う場合は、プレースホルダーを自分の情報に置き換えてください。

```bash
# SOCKS5（socks5h を使うと、ドメイン名の解決もプロキシ側で行います）
curl -x socks5h://USERNAME:PASSWORD@HOST:PORT https://www.anbovpn.com/ip

# HTTP
curl -x http://USERNAME:PASSWORD@HOST:PORT https://www.anbovpn.com/ip
```

応答には、ウェブサイトから見えるアドレスと所在地が表示されます。片方のプロトコルが失敗したら、同じ情報でもう片方を試してください。無料の[HTTPプロキシチェッカー](https://www.anbovpn.com/ja/tools/http-proxy-test)と[SOCKS5プロキシチェッカー](https://www.anbovpn.com/ja/tools/socks5-proxy-test)を使えば、複数のプロキシをまとめて確認できます。

プロキシの背後にあるアドレスの種類について詳しくは、[専用IPと共有IPの違い](/ja/posts/dedicated-ip-vs-shared-ip/)をご覧ください。
