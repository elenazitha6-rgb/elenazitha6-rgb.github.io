## SOCKS5 代理是什么？和 HTTP 代理有什么区别？

**SOCKS5 代理**是一种工作在更底层的代理协议：它只负责把你的 TCP 连接转发到指定的目标地址，不关心里面传的是网页、SSH 还是聊天软件的数据。**HTTP 代理**则看得懂 HTTP 请求，访问 HTTPS 网站时，通过 `CONNECT` 方法先建好一条隧道再转发。

| 对比项 | HTTP 代理 | SOCKS5 代理 |
|---|---|---|
| 看得懂什么 | HTTP 请求 | 不解析里面传的内容 |
| 常见用途 | 网页、API，HTTPS 经 `CONNECT` 隧道 | 任意 TCP 连接，如网页、SSH、聊天软件 |
| 认证方式 | HTTP 头里的代理认证，失败会返回 407 | 握手阶段的用户名和密码 |
| UDP | 不支持 | 协议里有定义，但不是每家服务商都开放 |
| 兼容性 | 浏览器、curl、各类爬虫库基本都有 | 有 SOCKS 设置项的软件、SSH 隧道等 |

## 软件里到底该填哪一个？

**看你的软件设置里写了什么，有什么填什么；两种都有时，网页类工具填 HTTP 最省心，非网页类软件填 SOCKS5 更通用。**

| 你要配置的对象 | 建议填 | 说明 |
|---|---|---|
| 浏览器环境（如指纹浏览器里的每个环境） | HTTP 或 SOCKS5 均可 | 按软件要求的格式填，批量导入见下文 |
| Python、Node 等脚本和爬虫库 | HTTP | 多数库直接支持；有的库想用 SOCKS5 还要额外装组件 |
| SSH、数据库客户端等非网页软件 | SOCKS5 | 不依赖 HTTP，什么 TCP 连接都能转发 |
| 要走 UDP 的程序 | 都不适合 | 安泊 VPN 的代理不支持 SOCKS5 UDP，请改用客户端 |

## 想看原理？两种代理是怎么握手的

HTTP 代理先收到一行明文的 `CONNECT 目标:端口`，然后建好隧道；SOCKS5 则是客户端和代理先做一次二进制握手、协商认证方式，再在请求里告诉代理目标地址。**两种方式都不会替你加密到代理这一跳。**

```text
CONNECT example.com:443 HTTP/1.1
Host: example.com:443
Proxy-Authorization: Basic ...
```

`CONNECT` 方法的定义见 [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110#name-connect)，SOCKS5 的握手见 [RFC 1928](https://www.rfc-editor.org/rfc/rfc1928)，用户名密码认证那一步见 [RFC 1929](https://www.rfc-editor.org/rfc/rfc1929)。两点常被忽略：`Proxy-Authorization: Basic` 只是 Base64 编码，不是加密；SOCKS5 的用户名密码认证同样是明文发送。

另外，有些网络环境对明文的 `CONNECT` 行和二进制的 SOCKS5 握手处理方式不同，所以偶尔会出现一种协议被重置、另一种能连上的情况。这只是排查时可以试的办法，不是规律，不同网络表现各异。

## 安泊 VPN 的代理 IP 支持哪些功能？

安泊 VPN 的代理 IP 给每个浏览器环境或脚本分配一个独立的代理账号，HTTP（含 HTTPS 隧道）和 SOCKS5 共用同一套凭据。以下信息已于 2026 年 11 月对照官网核对，以官网当前页面为准：

- **一行一条，复制即用。** 账户里按 `host:port:username:password`（主机、端口、用户名、密码）的单行格式给出，端口也在账户里查看；管理很多环境时，可以一键复制全部，直接粘贴到浏览器环境的批量导入里。
- **可选来源 IP 白名单。** 加入白名单的来源 IP，连接时可以免用户名和密码。
- **和固定 IP 共用资源。** 代理和固定 IP 用的是同一份流量、同一个 IP。选哪种 IP，可以先读 [固定 IP 和共享 IP 哪个好？一张表看懂怎么选](/zh/posts/dedicated-ip-vs-shared-ip/)。
- **有明确的限制。** 不支持 SOCKS5 UDP，不提供 25 端口（常用于邮件发信），也不提供内网访问。
- **按节点开通。** 某个 IP 下没有代理卡片，说明该节点还没开通代理，这个 IP 仍可通过客户端或订阅链接使用。

想了解当前在售的情况，看 [代理 IP 页面](https://www.anbolink.com/zh/proxy-ip)。

## 怎么测试代理通不通？

最直接的办法，是通过代理发一个请求到“回显你的地址”的服务，看返回的 IP 是不是代理的 IP。把下面的占位符换成你自己的信息：

```bash
# SOCKS5：socks5h 表示域名交给代理端解析（写成 socks5 则由本机解析）
curl -x socks5h://用户名:密码@主机:端口 https://www.anbolink.com/ip

# HTTP
curl -x http://用户名:密码@主机:端口 https://www.anbolink.com/ip
```

返回的就是网站眼里的你的地址。一批代理要一起检测，可以用免费的 [HTTP 代理检测工具](https://www.anbolink.com/zh/tools/http-proxy-test) 和 [SOCKS5 代理检测工具](https://www.anbolink.com/zh/tools/socks5-proxy-test)。

## 连不上怎么排查？

先对照现象，大多数问题都出在填写上。下面是最常见的几种：

| 现象 | 可能原因 | 怎么办 |
|---|---|---|
| 返回 407 | 用户名或密码不对，或来源 IP 不在白名单里 | 重新从账户里复制，或检查白名单 |
| 超时、Connection refused | 主机或端口填错，或当前网络有限制 | 对照账户里的信息，换另一种协议再试 |
| 密码里有 `@`、`:` 等符号时报错 | 在 URL 里需要先做 URL 编码 | 对密码做 URL 编码后再拼进地址 |
| 某个 IP 下没有代理信息 | 该节点还没开通代理 | 暂时用客户端或订阅链接 |

如果你还想让电视、游戏主机这类装不了客户端的设备也走同一个出口，读 [透明网关怎么用？电视、游戏主机不装 App 也能接入](/zh/posts/network-gateway-explained/)。
