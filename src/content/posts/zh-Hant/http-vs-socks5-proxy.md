## SOCKS5 代理是什麼？一句話搞懂

**SOCKS5 代理**是一種通用的轉送代理：你的程式告訴代理「我要連到哪個位址和埠號」，代理就替你建立 TCP 連線，並把雙方的資料原封不動地轉送，完全不解讀裡面傳的是什麼。協定規格見 [RFC 1928](https://www.rfc-editor.org/rfc/rfc1928)，帳號密碼驗證的部分則在 [RFC 1929](https://www.rfc-editor.org/rfc/rfc1929)。

可以把代理想成幫你跑腿的人。HTTP 代理像一位「看得懂網頁訂單的店員」：你把網頁請求交給他，他讀懂之後再去辦；SOCKS5 代理則像「只負責轉接的總機」：你說要接到哪個號碼，他幫你接通，你們聊什麼他不管。這也是為什麼 SOCKS5 能轉各種 TCP 連線，而 HTTP 代理最適合網頁類的工具。

## 到底選哪一個？不要看快慢，看你的軟體

選擇的依據是軟體的代理設定提供什麼，而不是哪一種比較快。如果軟體兩種都有，SOCKS5 通用性比較高，HTTP 則是最傳統、相容性最廣的選項。下表用「你手上的工具」來對照：

| 你在用的工具 | 建議選擇 | 原因 |
|---|---|---|
| 一般瀏覽器、多開瀏覽器環境的軟體 | 看軟體有哪個選項 | 多半兩種都支援，挑你設定起來順手的 |
| curl、爬蟲函式庫、API 測試工具 | HTTP 代理 | 網頁與 API 類工具對 HTTP 代理的支援最普遍 |
| SSH 通道、聊天軟體等非網頁程式 | SOCKS5 代理 | 不限於網頁協定，一個設定可以涵蓋多種 TCP 連線 |
| 需要 UDP 的程式，例如部分遊戲、語音通話 | 兩者都不適合 | 安泊 VPN 代理不支援 SOCKS5 UDP，請改用 VPN 用戶端 |

## 進階補充：一個 HTTPS 請求是怎麼穿過代理的？

透過 HTTP 代理連 HTTPS 網站時，用戶端會先送出一行純文字的 `CONNECT` 指令說明目的地，代理確認後建立通道，才開始轉送資料；SOCKS5 則是用戶端和代理先做一小段二進位的握手（包含驗證），再用精簡的二進位格式指定目的地。兩種方式的共通點是：代理都知道你要去哪裡，而單靠協定本身，也都不會替你到代理的那一段加密。

```text
CONNECT example.com:443 HTTP/1.1
Host: example.com:443
Proxy-Authorization: Basic ...
```

`CONNECT` 方法定義在 [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110#name-connect)。

小提醒：有些網路對純文字的 `CONNECT` 和二進位的 SOCKS5 握手處理方式不同，所以偶爾會遇到「HTTP 連不上、SOCKS5 卻可以」，或者反過來。遇到時，用同一組帳號改試另一種協定即可，把它當成排錯的一個步驟，而不是固定規律，因為不同網路的表現並不一樣。

## 三個常見迷思

代理協定最容易被誤解的，是速度、加密與適用範圍。釐清這三件事，可以少走很多冤枉路。

- **「SOCKS5 比較快。」** 兩者沒有誰天生更快，速度受網路路徑與代理伺服器影響。我們不提供速度或延遲數字，也不做這類承諾。
- **「SOCKS5 會加密我的連線。」** 不會。要保護內容，請確保你用的是 HTTPS 這類本身加密的協定。
- **「只要設了代理，所有軟體都會走代理。」** 不一定。有些程式不理會系統的代理設定，需要在程式自己的設定裡指定；想讓這類程式也走連線，可以改用用戶端的 TUN 模式。

## 安泊 VPN 的代理帳號怎麼用？

安泊 VPN 的 HTTP/SOCKS5 代理，讓每個瀏覽器環境或每支腳本都能擁有自己的代理帳號，一組帳密同時支援 HTTP（含 HTTPS 通道）和 SOCKS5。以下內容已於 2026 年 11 月對照官方網站查證。

- **一行格式，方便匯入。** 主機、埠號、帳號、密碼會以 `host:port:username:password` 的一行格式顯示在你的帳號裡，可以一次複製全部，貼進瀏覽器環境軟體就能用；埠號也都標示在帳號中。
- **可選的 IP 白名單。** 你可以另外設定來源 IP 白名單，名單內的位址連線時不必再輸入帳號密碼。
- **和固定 IP 共用資源。** 代理與固定 IP 共用同一份流量與同一個 IP。
- **有邊界。** 不支援 SOCKS5 UDP，也不開放 25 埠與內網連線。
- **按節點開通。** 某個 IP 底下沒有代理卡片，代表該節點還沒開通；這個 IP 仍可透過用戶端或訂閱連結使用。

目前提供的方案可以到 [代理 IP 頁面](https://www.anbovpn.com/zh-Hant/proxy-ip) 查看。如果你還不確定要用固定 IP 還是共享 IP，先看 [固定 IP 和共享 IP 差在哪](/zh-Hant/posts/dedicated-ip-vs-shared-ip/)。

## 設定完成後：怎麼驗證代理真的有生效？

驗證的方法很簡單：透過代理對一個會回報來源位址的服務發出請求，確認看到的是代理的位址，而不是你自己的。用 curl 的話，把大寫的部分換成你的資料：

```bash
# SOCKS5（socks5h 會讓代理端負責解析網域名稱）
curl -x socks5h://USERNAME:PASSWORD@HOST:PORT https://www.anbovpn.com/ip

# HTTP
curl -x http://USERNAME:PASSWORD@HOST:PORT https://www.anbovpn.com/ip
```

回傳的內容就是網站看到的位址與所在地。其中一種失敗時，用同樣的資料試另一種。如果有一批代理要檢查，可以用免費的 [HTTP 代理檢測工具](https://www.anbovpn.com/zh-Hant/tools/http-proxy-test) 與 [SOCKS5 代理檢測工具](https://www.anbovpn.com/zh-Hant/tools/socks5-proxy-test)，一次測完。

如果你想讓家裡不能裝 App 的裝置也走同一條連線，代理就不太適合，可以看 [透明閘道是什麼](/zh-Hant/posts/network-gateway-explained/)。
